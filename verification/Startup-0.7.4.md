# 0.7.4 开机自启动故障与验收

2026-11-22，两台安装 0.7.2 的 fnOS NAS 均出现启动异常。主 NAS 曾在应用中心显示启动成功，约 7 秒后被标记为异常退出，重装后无法打开。测试 NAS 安装后可手动启动，整机重启后卡在「启动中」。

## 故障原因

0.7.2 的启动脚本派生后台子进程后，立即用 `/proc/<PID>/cmdline` 核对可执行文件。子进程可能还在 Bash 中处理重定向，尚未载入 MiMoStudio。脚本会因此报告启动失败并移除 PID 文件，子进程随后仍可完成启动并独占 `instance.lock`。应用中心失去对该进程的跟踪，后续启动尝试因无法取得锁而退出。

- 主 NAS 上，重装前的进程仍持有 `instance.lock`。它的可执行文件已被卸载移除，当前安装没有可用的 Web Socket 或 PID 文件。应用私有 `service.log` 反复记录单实例锁冲突。
- 测试 NAS 同一轮开机中出现启动失败，随后仍能看到持锁进程及其 Web Socket。PID 文件指向后续尝试中已经退出的进程，`service.log` 同样记录了锁冲突。

## 修复

[启动脚本](../packaging/cmd/main)用 PID 和内核启动时钟判断刚派生的子进程是否仍存活，允许其完成 exec。[后端](../backend/Program.cs)启动并将 Web Socket 权限设为 `0600` 后，将自身 PID 写入私有目录中的 `server.ready`。脚本核对进程身份、就绪记录和 Socket 后才报告启动成功。启动失败时，脚本先结束已确认身份的子进程，再清理本次的 PID 和就绪记录。

## 验收结果

- **Linux/WSL 回归**通过 FIFO 延迟子进程 exec，并预置无监听者的 Socket 文件。[回归用例](../tests/startup.py)在旧脚本上复现提前退出，在 0.7.4 上通过延迟启动、重复启动、停止和再次启动检查。另有 6 项生命周期钩子检查通过。
- **构建与打包**通过 352 项 Release 后端测试和前端生产构建。官方 `fnpack` 生成 Linux x86-64 自包含 FPK，[包结构检查](../tests/package.py)通过。FPK 的 SHA-256 为 `1d708ec5c7b12f5bddf45e65a3fe220e8e529c3d502a93df4a1a5c6c8c38a791`。
- **测试 NAS 实测**通过应用中心将 0.7.2 原位升级到 0.7.4，验证应用级停止与启动，再重启整台 NAS。开机日志记录 `APP_AUTO_STARTED`，本轮开机未记录该应用的启动失败或崩溃事件。登录后从 fnOS 桌面图标打开工作台，网关会话 API 返回 HTTP 200。私有 Socket 对管理员身份返回 200，对无身份请求返回 403。升级和重启后，28 个原有私有文件逐一校验一致。
- **主 NAS 恢复**核对残留进程的身份及锁归属后，发送 `SIGTERM` 并通过应用中心重新启动。应用中心显示运行中，私有 Socket 上的管理端请求返回 HTTP 200。主 NAS 当次仍运行 0.7.2，整机重启验收在测试 NAS 的 0.7.4 上完成。
